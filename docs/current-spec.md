# 第1部 現行仕様

## 1. 概要とコンセプト

- PC(Mac / Windows)向けの、Unity 製の駐車練習シミュレーター【要望】
- 自分の車 **SUBARU インプレッサ SPORT** の寸法と最小回転半径を再現する【要望】
- 舞台は「時間が止まった町」。歩行者や走っている車はなく、停まっている車だけがある。自分だけが自由に運転の練習をできる【要望】
- 2D 俯瞰と 3D 運転席の視点がある【要望】。3D 外部視点もある【判断】
- 遊び方は2つ
  - **自由練習**: 町を走り、近くの駐車枠に停めて判定を受ける
  - **目的地ゲーム**: マップで選んだ区画まで走って停める【要望】

## 4. 車の動き(物理モデル)

物理エンジンの剛体は使わず、自前の運動学モデルで動かしています【判断】。

- **モデル**: 後輪軸の中心を基準にした二輪モデル。見た目の前輪はアッカーマン配置で切る
- **計算の刻み**: 10 ms ごと
- **加速**: アクセル開度 × 2.6 m/s²。最高速度に近づくほど弱まる。最高速度は前進 16.7 m/s(60 km/h)、後退 5.0 m/s(18 km/h)
- **減速**: 0.12 + 0.002 × 速度² + ブレーキ × 7.5 + パーキングブレーキ 6(m/s²)
- **P**: 20 m/s² で止める。**N**: 惰性で転がる
- **クリープ**(設定で ON のとき): 前進 約6 km/h、後退 約5 km/h に向けて 1.1 m/s² で加速
- **ペダル**: デジタル入力。押している間に踏み込みが増える
  - アクセル: 毎秒0.6ずつ増える(最初は0.05)。離すと毎秒3ずつ戻る
  - ブレーキ: 毎秒1.2ずつ増える(最初は0.08)。離すと毎秒4ずつ戻る。Space キーは即1.0
- **エンジン停止中**: 運転操作のうちシフトは受け付けない。アクセルによる加速は、ギアが P 固定なので結果的に起きない
- **切り返しの数え方**: 逆向きに 5 cm 以上動いたら1回
- **時間の数え方**: `driveTime` は操作を受け付けている間だけ進む(メニューやマップの表示中は止まる)

## 5. 運転操作と車の状態

### 5.1 エンジン【要望】

- スタート時と、スタート地点に戻ったときは **エンジン停止・P・パーキングブレーキ ON**
- **始動**: ブレーキを踏みながら L(キーボードは I)を **0.5秒** 長押し。始動するとシフトは P
- **停止**: P でブレーキを踏みながら ZL(キーボードは I)を **0.5秒** 長押し【判断】(要望は「長押し」だけで、時間の指定は始動の0.5秒のみ)
- 押し始めた時点で条件を満たしているときだけ数える。R から ZL で P に戻した勢いで止まらないようにするため【判断】
- エンジン停止中は画面中央に「ブレーキ(ジョイコン左の▼)を踏みながらLを長押しすると、エンジンが始動します。」と表示【要望】。キーボードでの操作も併記【判断】
- エンジンを止めると、近くの駐車枠で自動的に判定する【判断】

### 5.2 シフト

- P / R / N / D。Joy-Con の L で D 側へ1段(P→R→N→D)、ZL で P 側へ1段【要望】
- 速度が 0.4 m/s を超えているときは N 以外へ切り替えられない【判断】
- エンジン停止中は「エンジンを始動してください」と表示して受け付けない【判断】

### 5.3 電動パーキングブレーキ【判断】

- キーボードの B で ON / OFF。D か R でアクセルを踏むと自動で解除
- **Joy-Con には割り当てがない**(自動解除だけが働く)

### 5.4 ハンドル

- **キーボード**: A / D(← / →)で毎秒 450°(設定で 180〜900°)。Shift で2倍。C で中立へ戻す(毎秒 720°)。キーで回したハンドルは手を離しても戻らない
- **マウス**: M で ON / OFF。画面上のマウスの左右位置がハンドル角になる
- **Joy-Con 右スティック**【要望】: 倒した量に比例した速さで回す。離すと、手を離したハンドルのように中央へ戻る(止まっていても戻り、速く走っているほど速く戻る。毎秒 360〜900°)。R を押している間は戻らない
- 右スティックの遊び(デッドゾーン)は 0.25

### 5.5 クリープ【要望】

- 設定メニューで ON / OFF。**初期値は OFF**

### 6.2 Joy-Con (L)+(R)【要望】

L と R を左右の手に1本ずつ持つ想定です。

| ボタン | 操作 |
|---|---|
| 左の ▲ / ▼ | アクセル / ブレーキ |
| 右スティック 左右 | ハンドル |
| R(押している間) | ハンドルの角度を保持 |
| L / ZL | シフトを D 側 / P 側へ1段 |
| ▼ + L 長押し | エンジン始動 |
| ▼ + ZL 長押し | エンジン停止(P のとき) |
| ZR | 視点切替 |
| 左スティック | 視点の操作(7章) |
| 左スティック押し込み | 外部視点の仰角、2D のズームを初期値に戻す【判断】 |
| キャプチャーボタン | 設定メニュー |
| − | マップ |
| マップ内: 十字 / スティック、A、X、Y、− / B | 区画を選ぶ、決定、おまかせ、目的地をやめる、閉じる |

割り当てがないボタン: +、HOME、右スティック押し込み、SL / SR。A / B / X / Y はマップの中でだけ使う。

### 6.3 ゲームパッド(プロコンなど)【判断】

Joy-Con と同じ配置で読みます。東=A、南=B、北=X、西=Y、LB=L、RB=R、LT=ZL、RT=ZR、Start=キャプチャー、Select=−、十字=十字。トリガーもボタン扱い(アナログ量は使っていない)。

### 6.4 Joy-Con の接続方式【判断】

- Unity の Input System の上に、自前の HID ドライバー(`JoyConHID.cs`)を載せている
- 接続するとフル入力モード(レポート 0x30)に切り替えるコマンドを送り、アナログスティックを読む。成功したらプレイヤーランプを1つ点灯
- スティックの中立位置は、接続直後の数回の値で決める(接続中はスティックに触れない前提)。遊び 0.15
- 画面左上に接続状態を表示(緑●=フル入力モード、黄●=ボタンのみ、○=未接続)
- macOS で実機の接続を確認済み(13:00 ごろユーザーが確認)

## 10. 接触と脱輪【要望】

| 種類 | 対象 | 挙動 | 数え方 |
|---|---|---|---|
| **接触** | 車体(地上 0.25〜1.48 m の箱)かミラーが、他の車・壁・塀・ポール・電柱・信号柱・建物・家に当たる | 当たる直前の位置で **即停止**。警告音「ピーーー」(2.1 kHz)を最大3秒。その間はセンサー音を止める | 0.02 m/s 以上で当たったときに1回 |
| **輪止め** | タイヤが輪止めに当たる | 停止。「タイヤが輪止めに当たりました」と表示 | 数えない |
| **脱輪** | タイヤが縁石・歩道・植え込みに乗る | 止めずに乗り上げる。段差に当たるたびに速度が半分、降りるときは 0.85 倍。乗ったタイヤの位置に合わせて車体が傾く | 縁石に乗っていない状態から乗ったときに1回 |

## 11. 駐車判定

### 11.1 判定のタイミング

- エンジンを止めたとき(自動)。または Enter
- 対象は、車の中心から **9 m 以内でいちばん近い駐車枠**。目的地が設定されていて、その近くにいるときは目的地を優先する
- 自動判定では、枠に入っていない(下の「枠の近く」を満たさない)ときは何も出さない
- 判定結果は、エンジンをかけるか車が動き出すと自動で閉じる【要望】

### 11.2 測るもの

- **枠の近く**: 車の中心が枠から前後左右 1.5 m 以内で、向きのずれが 45° 未満
- **左右の余白**: 車体の四隅から、左右の白線の内側(車庫・縦列は縁石・塀)まで
- **角度のずれ**: 枠の向きとの差。前向き・バックのどちらで停めてもよい。縦列は進行方向向きだけ
- **はみ出し**: 通路側(縦列は枠の前後)へ車体が出ている量
- **縦列**: 縁石までの距離
- **接触・脱輪・切り返し**: 枠から 9 m 以内に入ってからの分だけ数える

### 11.3 採点(100点から減点)

| 項目 | 減点 |
|---|---|
| 角度のずれ | 1° につき 4点(最大 30) |
| 中心からの左右ずれ(縦列以外) | 1 cm につき 0.5点(最大 25) |
| 縁石までの距離(縦列) | 30 cm を超えた分 1 cm につき 0.6点(最大 25) |
| 白線を踏んでいる / はみ出している | 12点 / 30点 |
| 通路へのはみ出し | 10点 + 1 cm につき 0.4点(最大 30) |
| 接触 | 1回 25点 |
| 脱輪 | 1回 5点 |
| 切り返し | 無料の回数(縦列2回、ほか1回)を超えた分 1回 4点 |

ランク: S(95以上) / A(85以上) / B(70以上) / C(50以上) / D。減点がなければ「完璧です!」と表示します。

## 12. 目的地ゲーム【要望】

- − ボタン(N キー)でマップを開く。開いている間はゲームの時間と音が止まる
- マップには町全体の画像、自車、目的地の候補(空いている区画)を表示。到着したことがある区画は緑
- 「おまかせ」は、今いる場所から 30 m 以上離れた候補からランダムに選ぶ【判断】
- 目的地を決めると、現地の地面にオレンジの枠と、浮かんで回るひし形の目印を出す。車が 4.5 m まで近づくと目印は消える
- 画面右上に、車の向きを基準にした方向の矢印と直線距離を表示。10 m 以内で「到着」
- 目的地に停めてエンジンを切る(または Enter)と「目的地に到着!」として採点し、道のり・所要時間・道中の接触と脱輪・自己ベストを表示。「次の目的地」ですぐ次を選べる
- 目的地以外の枠で判定すると「ここは目的地ではありません」と表示する
- 自己ベストと到着回数は **アプリを終了すると消える**【判断】

## E. 設計・実装の課題

作り直すなら、次の点は構造から見直したほうがよいです。

1. **入力の処理が散らばっている**
   キーと Joy-Con の読み取りが `CarController`、`CameraRig`、`GameManager` に分かれ、それぞれ旧方式の `Input` と `Pad` を直接読んでいます。割り当てを変えるたびに複数のファイルを直す必要があり、実際に4回の変更で毎回そうなりました。「操作の名前(アクセル、シフト上げ など)」と「ボタン」を対応づける層を1つ作り、割り当て表を1か所で持つべきです。Input System の Action 機能に一本化するかも検討の余地があります。

2. **`GameManager` と `HUD` に役割が集まりすぎている**
   `GameManager` は判定・目的地ゲーム・マップ操作・キー操作・自動撮影を、`HUD` は全画面と設定メニューと一時停止の制御を持っています。ゲームの状態(運転中、メニュー、マップ、判定結果)を1つの状態として管理する仕組みがなく、`menuOpen`、`mapOpen`、`showResult`、`helpOpen` のフラグの組み合わせで分岐しています。

3. **町のデータがコードに直書きされている**
   `TownBuilder.cs` に座標が数百か所あり、スタート地点や区域は `TownBuilder` と `WorldBuilder` の両方で足しています(`WorldBuilder` が「交差点の手前」を2番目に差し込むなど)。マップの表示範囲(`MapView.Area`)も別の場所に直書きです。町の配置をデータ(道路網、区画の列、スタート地点、区域)として定義し、そこから生成する形にすると、配置の変更や区画の種類の追加がしやすくなります。

4. **名前の文字列に頼った処理がある**
   マップで区域名を出すとき「十字路の交差点」という名前で除外しています。自動撮影は「コンビニ」で始まる区画を探しています。

5. **調整値が散らばっている**
   ペダルの増え方、ハンドルの戻る速さ、減速、判定の減点、センサーの距離、カメラの角度などが各ファイルの定数になっています。調整用の値を1か所(設定ファイルなど)にまとめると、実機で試しながら直しやすくなります。

6. **画面が IMGUI**
   IMGUI は試作には手軽ですが、レイアウトの調整や、コントローラーでのメニュー操作(A の3 の問題)に向いていません。UI Toolkit などへの移行を検討します。

7. **保存の仕組みがない**
   設定も自己ベストも保存しません(C8、C9)。

8. **テストがない**
   確認は自動スクリーンショットと Claude の数値テスト(その場限り)だけです。最小回転半径、判定の点数、縁石の扱いなどは自動テストにしやすい部分です。

9. **小さな不具合・紛らわしさ**
   - `ParkingSensors.Measure` の変数 `moving` は実際には「ゆっくり走っている」を表しており、名前が逆
   - エンジン停止中でも物理計算ではアクセルが効く作りで、ギアが P 固定のおかげで動かないだけ
   - Joy-Con の中立位置は接続直後の値で決めるため、接続中にスティックに触れるとずれる

## F. 作り直す前に決めたいこと

上の内容を踏まえて、仕様を固めるために決める必要があるものです。

1. **作り直しの範囲**: Unity のまま全体の構造を作り直すのか、エンジンや UI の方式から選び直すのか。Joy-Con の自前ドライバーは実機で動いているので、流用するか
2. **遊び方の中心**: 自由練習と目的地ゲームのどちらを主にするか。区画の寸法を変えて試すモード(A の2)を戻すか
3. **区画の種類**: U字と I字、区画幅、通路幅、前向き / バック / 縦列、柱や壁などの組み合わせのうち、町に何を用意するか(A の1・2、C3)
4. **操作機器**: Joy-Con だけで全操作できるようにするか。キーボード・マウス・ゲームパッドの位置づけ(A の3)
5. **未決事項 C1〜C12** の決定
6. **確認の進め方**: 実機で確かめる項目(D)を、作り直しのどの段階で誰が確かめるか
